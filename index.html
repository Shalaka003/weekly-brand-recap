Weekly Brand Recap

Every week, CMG gets each brand’s sales data from SPINS and retailer data portals. Weekly Brand Recap turns that data into a short, checked update for each brand, inside CMG Central.

Why build it: A brand update has to get three things right. Files from different sources need one format. Every number has to match its source. And because CMG holds many brands’ data in one place, each brand must see only its own. This workflow handles all three, so CMG’s team reviews a checked draft.

Who it’s for: CMG’s own team first, the people who prepare and approve brand updates. Brand partners second: they get an update they can trust, in the CMG Brand Portal.

Try it: Open the clickable prototype (sample data). Fix the flagged Whole Foods number, approve the recap, then view it as Sample Brand and as another brand.

How it works

StepWhat happensWhat keeps it right
  1. Collect

    Retailer portal and SPINS files come in by connector, MCP or upload.

    If a file is missing, the recap says which one. It never reuses old data.

  2. Map

    Each file’s columns are matched to one CMG format. For example, “Dollars” and “Net Sales” both become Sales $.

    A new column name goes to Operations to map once. Nothing is guessed.

  3. Draft

    The AI assistant writes each brand’s recap from that brand’s rows only.

    It never sees another brand’s data.

  4. Check

    A separate step matches every number in the draft to its source row.

    A number that doesn’t match is flagged and blocks approval.

  5. Approve

    The brand’s CMG team fixes anything flagged and approves.

    Every recap records who approved it, and when.

  6. Publish

    The recap posts to the CMG Brand Portal.

    Each brand sees only its own approved recaps.

Rollout plan

TimingWhat I’d doWhen to move forward
  1. Weeks 1–2

    Map today’s process

    Sit with Category Insights and Client Services. Time each step of how brand updates are made today, to set the baseline.

    Agree the scope

    The VP of Operations signs off the process map, the baseline time and the targets.

  2. Weeks 3–4

    Build and test

    Set up the mappings, the AI assistant, the check and the access rules in CMG Central. Run every test on last month’s real files.

    Ready for a pilot

    Every test passes, including a planted wrong number that the check must catch.

  3. Weeks 5–8

    Pilot with three brands

    Run it side by side with today’s process. Get feedback from each brand’s CMG team every week, and fix what comes up.

    Ready to roll out

    The numbers match today’s process, and the teams prefer the new way.

  4. Weeks 9–12

    Train and roll out

    A 15-minute training on real drafts: open, fix one flag, approve. Add brands in waves, with a one-page guide for brand partners.

    Agree what’s next

    8 in 10 weekly recaps run through it. Then pick the next workflow using the numbers below.

Questions I’d ask in week one

  • Source of truth

    When SPINS and a retailer portal disagree, which number goes in the recap?

  • Access

    Do brand partners use CMG Central directly, or only the Brand Portal? That decides where the access rules live.

  • Starting point

    Who prepares brand updates today, and which one takes longest? The pilot should start there.

What I’d report to the VP of Operations

Set the baseline in weeks 1–2, then report every month: what shipped, what broke, what’s next.

  • Usage: The share of weekly recaps that run through the workflow.
  • Time saved: Minutes per recap, compared with the baseline.
  • Data accuracy: The share of numbers that pass the check the first time.
  • Failure rate: Runs that needed a manual fix, and why.
  • Feedback: What CMG teams and brand partners say.
